A pick only counts if the jaws hold the cube. The arm is the official SO-101 model with force-limited servos, so it sags under load and the controller has to correct for it. The simulation is kinder than a real table: perfect depth, no sensor noise, ideal lighting. Success is read from the physics state, never from the camera.

Frequently asked questions

Straight answers about the sim, the keys and the real arm.

Is this a real robot?

No. Today it is a MuJoCo simulation of the official SO-101 model with force-limited servos, so a pick only succeeds if the jaws actually hold the cube. A LeRobot follower can be attached in mirror mode (it repeats the simulated arm's joint targets), but that path has never been run on hardware.

What needs an API key?

The Muse planner and SAM 3.1 both run on the Meta Model API and need MODEL_API_KEY. Without it they report setup required. Clicking an object and a target works with no key, using SAM 2.1 locally.

How do you know a pick worked?

From the physics state, not the camera: the cube's centre has to sit inside the tray walls and rest low. Perception is scored separately against MuJoCo's own segmentation.

Can an agent drive it?

Yes. An MCP server exposes look, find, pick_place and status, and the dashboard and HTTP API show the same runs.
