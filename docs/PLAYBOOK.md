# Robot project playbook

What we learned building the Thenar Walker (ESP32-S3 rover + 6-servo arm, phone control), written so a new project
can reuse it. Each section names the file in this repo that does it for real — copy from there.

> Shared base, copied from github.com/nickthelegend/thenar-walker `docs/PLAYBOOK.md`. The file paths below are in
> that repo (clone it next to this one); the Raspberry Pi port of the firmware lives there in `pi/`.

## 1. How the project is organised
- **Everything is generated by scripts** and checked by scripts: CAD (`cad/tools/*.py`), print plates
  (`make_plates.py` → `cad/print/`), drawings, reports, the build book PDF, even the assembly video. Re-running a
  script must reproduce the file; hand-edited outputs drift.
- **One dimensions file** (`cad/tools/design.py`): every size, position and rule limit lives there; parts, checks,
  sims and docs import it.
- **Checks write evidence** (`cad/evidence/*.json`): fit/clearance checks (nothing intersects, clearance ≥ rule,
  fits the start box, fits the printer bed) print pass/fail with numbers. Show the numbers, not "should fit".
- **Secrets stay out of git**: `team_config.h` from `firmware/tools/new_key.py`, listed in `.gitignore`.
- **Big binaries go to GitHub releases**, not the repo.

## 2. ESP32 firmware patterns (`firmware/thenar_phone/thenar_phone.ino`)
- **Toolchain**: arduino-cli, `esp32:esp32` core 3.x, FQBN `esp32:esp32:esp32s3`. Boards with a CP210x/CH340 use the
  default "USB CDC on boot: disabled" upload over UART. If upload says the port is busy, something (a Web Serial tab,
  a serial monitor) holds it.
- **S3 vs classic ESP32**: different safe GPIOs; the S3 has no classic Bluetooth (BLE only). Keep pins in one place.
- **Servos via PCA9685**: prescale `round(25e6 / (4096 · 50)) − 1`; MODE1 sleep → prescale → MODE2 totem-pole →
  wake + auto-increment; start with ALL_LED full-off (reg 0xFD = 0x10) and OE high so every servo is limp at boot.
  Pulse write: LEDn_ON = 0, LEDn_OFF = count. Limp one channel = full-off bit (0x10 in LEDn_OFF_H).
- **First pulse jumps**: a hobby servo has no position feedback, so the first pulse moves at full speed. Start limp,
  make "arm on" explicit, slew-limit every later move (deg/s), warn the operator to hold the arm near the target.
- **DC motors via Cytron MDD10A** (sign-magnitude): DIR pin = direction, PWM 20 kHz = speed; PWM low = brake.
- **Skid-steer drive** (`ThenarLink/tw_robot.h`): deadband 5 %; separate speed and turn scales per speed mode; a
  spin-in-place breakaway floor (35 %) or gentle turn inputs do nothing on grippy tyres; ramp up (2.5/s) but stop
  instantly; reversing goes through zero.
- **Failsafe**: the operator side sends a heartbeat; the robot times out (300 ms here) → wheels 0, joint motion 0, arm
  holds with PWM on (a limp MG996R drops what it holds). STOP is a **latch** released only when the stick is centred;
  keep the last real stick value while latched, or the latch releases itself on the next loop.
- **Calibration record in NVS** (`ThenarLink/tw_armcal.h`): struct + magic + version + CRC32; validate each joint on
  a **copy** before accepting it, so a bad number can never make the stored record unloadable. Flashing keeps NVS.
- **Serial line protocol** for tools: one command per line, one reply line starting `OK` or `ERR`. Easy to drive from
  Web Serial, Python (pyserial) or a terminal, and easy to test.

## 3. Low-latency phone control (no app needed)
- Robot = Wi-Fi access point (WPA2, max 1 station) + a web page compiled into the firmware (raw string literal).
- After load, use **one WebSocket** (here a ~120-line RFC 6455 server on `WiFiServer` port 81: SHA1Builder +
  base64 for the handshake, masked client frames, one `write()` per frame) — no request/response polling.
- Latency switches: `client.setNoDelay(true)`, `WiFi.setSleep(false)` + `esp_wifi_set_ps(WIFI_PS_NONE)`, 100 Hz loop.
- Page side: pointer events with `setPointerCapture`, coalesce sends to one per `requestAnimationFrame`, heartbeat
  every 40 ms, ping every 500 ms and show the round trip. Hold-to-move buttons send a *speed*; the robot integrates
  it, so a late packet can't cause jerks; release sends 0, and the link timeout also zeroes it.
- Android: turn **mobile data off** (a Wi-Fi with no internet otherwise loses traffic to 4G). Browsers only give
  pages gamepad / wake-lock / Web Serial access on secure contexts (https or localhost) — plain http on 192.168.4.1
  gets none of them.
- A native app can fix the routing with `ConnectivityManager.bindProcessToNetwork` (see `mobile/modules/thenar-native`).

## 4. Servo calibration that works (`docs/calibrator/`)
Two physical reference poses per joint (A and B, e.g. "upper arm vertical" and "45° forward", angles taken from the
CAD/sim), jog each servo to them, record the pulses, then
`k = (B − A)/(qB − qA)`, `us_per_deg = |k|`, `sign = sign(k)`, `zero = A − qA · k`.
Also record two **safe ends** (pulses the joint must never pass) and clamp everything to them. Mark each joint done;
only done joints may power up. Keep the tool's state in localStorage, and remember it is per origin **including port**.

## 5. CAD without fighting SolidWorks
- SolidWorks COM from Python (pywin32) works for parametric parts, but text sketches and big rebuilds can hang it.
  Never close documents you didn't open; the user may have other work open.
- **Mesh CAD** (`cad/tools/tub_v2.py`): trimesh + manifold3d booleans on boxes/cylinders, envelopes of every bought
  part (motors, boards, battery, wheels), then automated checks: no intersections, clearances, bed fit, start-box fit.
- Engraving text on a wall: decide the reading direction with a **camera projection** (screen-right = view_dir × up),
  never by flipping axes by hand — mirrored logos shipped once.
- Wheel ground clearance = wheel radius − how far the lowest part hangs below the axle.

## 6. Printing
- Plates are generated (`make_plates.py`) and sliced by CLI. Bambu Studio CLI exit −64 = an object in the P1S
  front-left exclusion zone (keep x ≥ 20 mm). Creality Print 7.x CLI can't take Orca-style slicing arguments.
- Only quote print times from an actual slice. More walls = slower; tyres print as flat TPU strips (faster, no
  supports) and wrap onto the hub.

## 7. Simulation (`sim/`)
MuJoCo model of robot + arena, with the **real firmware logic** compiled into a bridge executable (stdin/stdout,
flush every line — MSVC ignores line buffering). Run missions with env-var motor parameters to see where weak motors
fail (speed breakers) before buying. Keep tyre friction honest: skid-steer turning is scrub-limited.

## 8. Testing without the hardware
- Write a **mock robot** that follows the firmware's rules (slew, clamps, latch, timeout), not just its API
  (`mobile/test/mock_robot.py`), and an end-to-end test that drives the real client code against it
  (`mobile/test/e2e.test.ts`). It caught a real firmware bug (the STOP latch releasing itself).
- Make Node as strict as browsers where it matters (e.g. calling `fetch` unbound throws "Illegal invocation" in
  browsers only).
- Browser-pane quirks: a hidden pane pauses `requestAnimationFrame`; headless Chrome can't go below ~500 px wide.

## 9. Things that cost us time
| Symptom | Cause / fix |
|---|---|
| Shell-written C code has broken `'\n'` | Git Bash heredoc collapsed backslashes — write files with an editor tool |
| `.bat` launcher "cancelled due to restrictions" | Windows policy — run `python script.py` instead |
| Controller won't pair with the ESP32-S3 | S3 = BLE only; most cheap pads are classic BT or 2.4 GHz dongles — use the phone |
| Gamepad invisible to a web page | needs https/localhost; Brave Shields can hide it — use Chrome/Edge |
| Arm calibration "lost" | it was in the browser's localStorage for another port — check every origin |
| Servo ignores small steps then oscillates | worn/clone MG996R pot or power sag — swap servo between channels to isolate |
| Web slider at 0 shows at the minimum | `@react-native-community/slider` web uses `value || min` — pass 1e-6 |
| Upload fails "port busy" | Web Serial tab or monitor holds the COM port |
